## 构建与运行

```bash
# 构建整个解决方案
dotnet build SMMS.slnx

# Release 构建（发布前必做，会走代码分析）
dotnet build SMMS.slnx -c Release

dotnet run --project src/SMMS.Desktop
```

Release 配置开启了可空引用类型与代码分析，提交前请确保 **0 错误 0 警告**。

## 分层约定

依赖方向必须保持单向：

```
Desktop → UseCases → Core
    ↓
Infrastructure（只在 Desktop 启动时装配）
```

**Core** 不引用任何第三方库，也不碰文件系统——只放模型和纯算法。这样核心逻辑可以直接单测，不需要临时目录。

**UseCases** 通过构造函数注入接口（如 `IProfileManifestStore`），不直接 `new` 基础设施类型。

**Infrastructure** 实现 `Core` 里定义的接口，向上只被 `Desktop` 的 DI 容器看到。

### 新增一个业务能力

1. `Core` 加模型 / 接口（如需要）
2. `UseCases` 加服务，构造函数注入依赖
3. `Infrastructure` 实现接口（如涉及平台 API）
4. `ServiceCollectionExtensions` 注册
5. `Desktop` 层加 ViewModel 与视图

## 关键实现说明

### 配置档与路径

```csharp
// 普通档：独立的 Mods 目录
<game>\_smms\profiles\<id>\Mods

// 内置档：直接映射游戏自己的 Mods
<game>\Mods
```

`ModProfile.CreateDefault()` 返回的就是后者，`IsBuiltIn = true`，不可改名/删除。

### 模组启用 / 停用

不移动文件，只重命名目录为 `<name>.disabled`。扫描器识别后缀并标记状态。

好处：切换瞬间完成，不会出现「复制一半断电」的中间态。

### 拖入更新的匹配逻辑

**按 `UniqueID` 匹配，不按文件夹名**。玩家或作者都可能改目录名，用名字匹配会把更新误判成新增，导致同时存在两份。

```csharp
// 伪代码
var existing = installed.FirstOrDefault(m => m.UniqueId == incoming.UniqueId);
if (existing is not null) → 更新（保留 config.json，替换其余文件）
else → 新增
```

### 快照增量

`Create()` 时取该档最新快照作为基准，逐文件比对「长度 + 最后修改时间」：

```csharp
if (相同 && CreateHardLink(target, previous, IntPtr.Zero))
    return;              // 共享磁盘数据，不占空间
File.Copy(...);          // 否则真实复制
```

跨卷或非 NTFS 时 `CreateHardLink` 返回 false，自动退化为复制，不报错。

**恢复时必须传 `previousRoot: null`**，强制全量展开，否则恢复出的文件会和快照建立硬链接，玩家改动会污染快照。

### 界面布局的两个坑

**1. 宽度切换导致的抖动**

按钮与进度条互换显示时，若两者宽度不同，整组会收缩，把相邻控件推着走。用固定宽度的容器包住两态：

```xml
<Panel Width="96">
    <Button Width="96" IsVisible="{Binding !IsBusy}"/>
    <ProgressBar Width="96" IsVisible="{Binding IsBusy}"/>
</Panel>
```

**2. ComboBox 选项刷新**

语言切换时如果 `Clear()` 再重填，`SelectedIndex` 会掉到 -1，反向写回 ViewModel 又触发一次刷新。改成原地替换元素：

```csharp
Options[0] = ...;    // 而不是 Clear() + Add()
```

## 测试

```bash
dotnet test SMMS.slnx
dotnet test SMMS.slnx -c Release
```

共 82 个测试：

| 项目 | 数量 | 覆盖 |
|---|---|---|
| SMMS.Core.Tests | 24 | manifest 解析、版本比较、模型逻辑 |
| SMMS.UseCases.Tests | 58 | 配置档、模组切换、快照、导入更新、预检 |

测试用 `TempGameDirectory` 创建真实临时目录（非 mock 文件系统），验证完自动清理。原因是很多 bug 只在真实 IO 下出现（编码、长路径、文件锁）。

### 写新测试的建议

- 涉及文件的，用 `TempGameDirectory`，不要 mock
- 断言放在行为上（`Assert.Equal("1", outcome.Arguments[1])`），不要断言实现细节
- 边界条件至少覆盖：空目录、目录不存在、文件被占用

## 发布

### 两种形态

```bash
# 框架依赖：约 38 MB，目标机需 .NET 10 运行时
dotnet publish src/SMMS.Desktop/SMMS.Desktop.csproj \
  -c Release -r win-x64 --self-contained false -o publish/fd

# 自包含：约 200 MB，解压即用
dotnet publish src/SMMS.Desktop/SMMS.Desktop.csproj \
  -c Release -r win-x64 --self-contained true -o publish/standalone
```

区别与选用场景见 [05-版本说明](05-版本说明.md)。

### 发布前检查清单

- [ ] `dotnet build -c Release` 零警告
- [ ] `dotnet test -c Release` 全绿
- [ ] 发布目录无本地配置（`settings.json`、`logs`、`snapshots`）
- [ ] exe 图标已嵌入（对比体积或字节比对）

## 调试技巧

### 无人值守截图

设置环境变量后启动，程序会在布局稳定后把窗口渲染成 PNG：

```bash
SMMS_START_PAGE=mods SMMS_SCREENSHOT=/tmp/mods.png dotnet run --project src/SMMS.Desktop
```

| 变量 | 作用 |
|---|---|
| `SMMS_START_PAGE` | 启动直接进入某页（`launchpad` / `profiles` / `mods` / `vanity` / `discover` / `updates` / `diagnostics` / `settings`） |
| `SMMS_SCREENSHOT` | 截图输出路径 |
| `SMMS_SCREENSHOT_DELAY` | 延迟秒数，默认 3（页面异步加载时可调大） |
| `SMMS_CHECKING_DEMO=1` | 强制进入「检查更新中」状态，用于验证布局 |
| `SMMS_REFRESH_DEMO=1` | 启动后自动触发刷新 |

> 注意：该功能在 `dotnet run` 下验证通过；直接用发布产物的 exe 启动时截图不稳定，仅作开发期诊断用。

### 日志

```bash
%APPDATA%\SMMS\logs\smms-YYYYMMDD.log
```

Serilog 按天滚动。排查问题先看 `[ERR]` 级别的记录。
