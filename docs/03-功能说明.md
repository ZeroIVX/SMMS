## 首次启动

程序启动后自动扫描 Steam 与 GOG 的安装记录（注册表 + `libraryfolders.vdf`），找到星露谷物语后直接进入启动台。多库、多盘都能识别。

若未找到，可在设置页手动指定游戏根目录。判断标准是目录下存在 `Stardew Valley.exe`。

**默认配置档直接映射游戏根目录的 `Mods`**，所以：

- 已装 SMAPI + 模组的玩家，打开就能看到现有环境
- 没装 SMAPI 的机器上，该目录不存在，会提示模组目录缺失（点「去设置」无法修改，因为它是内置档的固定路径）

## 启动台

回答一个问题：**现在能不能开，开之前要不要处理什么**。

| 区域 | 作用 |
|---|---|
| 环境卡 | 当前档位名称、状态徽章、模组数、缺失依赖与冲突统计 |
| 启动按钮 | 按当前档位启动；不可启动时置灰并给出原因 |
| 快捷操作 | 拖入安装、立即备份 |
| 待处理项 | 缺失依赖、版本冲突、SMAPI 需要更新等，按严重程度排序 |
| 最近备份 | 最近 3 份快照，可直接回滚 |
| 切换环境 | 快速切换配置档 |

启动模式有两种：**SMAPI 模式**（带模组）与**原版模式**（不带模组，用于排查问题）。

## 配置档

### 为什么要分档

不同玩法需要的模组完全不同。原版纯净档、轻度美化、大型整合包放一起会互相干扰，分档后各自独立。

### 操作

| 操作 | 说明 |
|---|---|
| 切换 | 点「设为当前」，之后启动都用这个档 |
| 复制 | 连模组一起复制出一份新档，用于「在现有基础上改改试试」 |
| 重命名 | 昵称，可含中文 |
| 导出 | 仅清单（几 KB）或连同模组（数百 MB） |
| 删除 | 内置档不可删 |

### 排序

- **原版**固定第 1 位、**默认**固定第 2 位，位置由语义决定，不参与手动排序
- 第 3 位起可手动调整：卡片上的 `↑` `↓` 按钮，首项上移与末项下移自动禁用
- 顺序保存到配置文件，重启保持

### 隔离级别

| 模式 | 隔离内容 | 适用 |
|---|---|---|
| 仅模组 | 只隔离 `Mods` 目录 | 大多数场景，省空间 |
| 完整实例 | 独立游戏副本 + 存档 | 需要不同游戏版本、或多存档隔离 |

创建时选择，之后不可更改。

## 模组

### 列表信息

每行显示：

```
①  ● Automate                                   3 个依赖   1.28.4   [开关]
     Pathoschild.Automate · 代码模组 · 含中文
     [备注] 自动化收菜
```

- 序号：`Mods` 目录内的加载顺序
- 状态点：绿色正常，琥珀色有风险（清单解析失败、实例丢失）
- 备注：玩家自己写的说明，带紫色标签，与作者简介区分

### 操作

| 操作 | 说明 |
|---|---|
| 启用 / 停用 | 重命名目录为 `.disabled`，不改文件内容，可随时恢复 |
| 备注 | 双击或详情面板内编辑，支持多行 |
| 详情面板 | 依赖 / 被依赖清单、文件清单、路径 |
| 搜索 | 匹配名称、唯一 ID、备注 |
| 筛选 | 全部 / 有风险 / 可更新 / 已禁用 |
| 排序 | 加载顺序 / 名称 / 更新状态 |

### 拖入安装

把 zip / 7z 拖进模组页即可：

- 自动识别包内模组结构（含嵌套目录）
- 按 `UniqueID` 判断是新增还是更新，**文件夹改名也能正确匹配**
- 更新时保留玩家的 `config.json`
- 检测到降级（新版本号更低）会先询问
- 更新前自动建快照，失败则中止

## 美化包

分两栏，语义不同：

### 资源替换包（XNB 覆盖）

游戏贴图/音效的直接替换。**同一时间只能生效一套**，因为覆盖的是同一批文件。

用开关切换：打开即应用（自动停用其他包），关闭即回到原版。

### Content Patcher 包

通过 CP 框架加载的内容包，**可以多套共存**，各自独立开关。

## 更新与快照

### 更新检查

联网比对 smapi.io 上的版本数据，列出：

- 可更新（显示当前版本 → 最新版本）
- 不兼容（当前 SMAPI 版本不支持）
- 未知（未在 smapi.io 收录，常见于私模）

### 可回滚节点

页面下方展示最近快照，可一键回滚。右侧有「立即备份」按钮，随时手动留档。

## 设置与诊断

**设置**：语言、游戏路径、翻译服务、NXM 协议注册。

**诊断**：SMAPI 版本、游戏版本、模组目录可写性、日志位置，用于排查「为什么点启动没反应」。

## 快照策略详解

快照是**整个 `Mods` 目录的副本**，但用硬链接做增量，所以不会成倍占空间。

### 四类快照

| 类型 | 何时产生 | 保留策略 |
|---|---|---|
| 手动 | 点「立即备份」 | **永不自动清理** |
| 启动前 | 每次启动游戏前 | 只留最新 1 份 |
| 更新前 | 拖入新版本更新模组 | 最近 5 份 |
| 恢复前 | 执行回滚操作 | 最近 5 份 |

「启动前」那份代表**上次能正常启动的状态**，游戏崩了、模组打架了，退回去就是能跑的样子。

### 增量原理

内容未变的文件（长度 + 修改时间一致）与上一份快照建立 NTFS 硬链接，两份路径指向同一份磁盘数据，不额外占用空间。只有改过的文件才真正复制。

**每个快照仍是完整目录树**，所以：

- 恢复逻辑简单，不需要按顺序应用补丁链
- 删除任意一份快照，其他快照的数据都还在

### 恢复时的一个细节

恢复采用**全量展开**，不继承硬链接关系。否则恢复出来的文件会和快照共享数据——你在游戏里改了配置，快照里的对应文件跟着变，备份就失去意义了。

## 常见问题

**Q：点启动没反应？**

看诊断页，或 `%APPDATA%\SMMS\logs\` 当日日志。常见原因：SMAPI 未安装、游戏正在运行、档位指向的目录不存在。

**Q：切换档位后游戏里还是旧模组？**

星露谷只在启动时读取 `Mods`，切换后需要重新启动游戏，不能热切换。

**Q：更新模组后想退回？**

看「最近备份」或版本页的「可回滚节点」，找标签为「更新模组前」的那份。

**Q：占用空间越来越大？**

快照是主要来源。手动的永久保留，其余自动清理。可在版本页查看各快照的实际占用，手动删除不用的。

**Q：能不能装到游戏目录里？**

不建议。程序会在游戏目录下创建 `_smms` 工作区（配置档、快照、备份），放进游戏目录会让目录结构混乱，卸载时也不好清理。
